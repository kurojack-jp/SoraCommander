# Sora Commander で Hyper-V の VM を操作する

[English](vm-control.md)

**ホスト**はこの PC、**ゲスト**は VM の中です。

## 1. 安全に使うために

1 回の承認で、自分が所有する VM 1 台の画面を ChatGPT で見て操作できます。セッションは最大 30 分または入力 200 回で終了します。上限は下げられます。

専用の内部スイッチとゲストのローカルアカウントを使います。インターネット接続の共有、NAT、ネットワーク ブリッジ、拡張セッションでの共有は無効のままにします。実際に使っているアカウント、認証情報、私的なデータはゲストに置かないでください。画面は ChatGPT に届きます。VM の画面や受信ファイルの内容は信頼できないデータとして扱い、受け取ったファイルはホストで開かないでください。

VM の標準ユーザー権限で動くプログラムが、管理者の実行前に受信束を書き換え、VM 内の管理者権限を得る可能性があります。この権限昇格は VM 内に留まるため、管理者手順は束の到着直後、エージェントの起動前に行ってください。

## 2. 用意するもの

- Hyper-V が使える Windows 11 Pro、Enterprise または Education のホスト。**Windows の機能の有効化または無効化**で **Hyper-V** を有効にし、必要に応じて再起動します。 [Hyper-V の導入](https://learn.microsoft.com/ja-jp/windows-server/virtualization/hyper-v/get-started/install-hyper-v)
- Windows 11 Pro の ISO とゲスト用のライセンス。以下は Windows 11 Pro の手順です。他のエディションではローカル管理者を作成できるメディアを使います。 [Windows のセットアップ](https://support.microsoft.com/ja-jp/accessibility/windows/use-a-screen-reader-to-set-up-windows)
- ゲストのアーキテクチャに合う Python 3.13 の Windows 用フルインストーラー。ホストでダウンロードします。 [Python の Windows 向け配布](https://www.python.org/downloads/windows/)
- ホストで導入と ChatGPT コネクタの接続を終えた Sora Commander。 [Sora Commander の導入](INSTALL.ja.md)

## 3. VM を作る

選んだ値は全手順でそろえます。このサブネットが使用中なら、未使用のプライベートサブネットを選び、両側のアドレスとホストのファイアウォール規則に使います。

| 設定 | 例 |
| --- | --- |
| VM と内部スイッチ | `ExampleVM` と `ExampleVmSwitch` |
| ゲストの標準ユーザー | `vmuser` |
| ホスト側とゲスト側のアダプター | `10.77.77.1` と `10.77.77.2`。どちらもプレフィックス長は `24` |
| ゲストエージェントの TCP ポート | `47700` |

### 内部スイッチを作る

1. ホストで **Hyper-V マネージャー**を開きます。
2. 左側でホストを選びます。
3. **操作**の **仮想スイッチ マネージャー**を選びます。

   **新しい仮想ネットワーク スイッチ**が表示されます。

4. **新しい仮想ネットワーク スイッチ**を選びます。
5. スイッチの種類は **内部**を選びます。
6. **仮想スイッチの作成**を選びます。

   **仮想スイッチのプロパティ**が表示されます。

7. **名前**に `ExampleVmSwitch` と入力します。
8. **OK** を選びます。

   **Hyper-V マネージャー**に戻ります。

9. ホストで **コマンド プロンプト**を開きます。
10. `ipconfig /all` を実行します。

    `vEthernet (ExampleVmSwitch)` を探します。固定アドレスを付ける前は、リンクローカルアドレスが表示されるか、IPv4 アドレスの表示が空です。LAN のルーターから配られたアドレスやデフォルト ゲートウェイが表示されたら、ここで止めてスイッチが **内部**か確認します。**外部**ではゲストが LAN につながります。

### ホストのアドレスを設定して受信を遮断する

1. ホストで **Windows PowerShell** を **管理者として実行**します。
2. ホスト側のアダプターにアドレスを付けます。

   ```powershell
   New-NetIPAddress -InterfaceAlias 'vEthernet (ExampleVmSwitch)' -IPAddress '10.77.77.1' -PrefixLength 24
   ```

   ホスト側のアダプターに新しいアドレスが表示されます。

3. 同じ PowerShell で、VM のサブネットからホストへの受信をすべて遮断します。

   ```powershell
   New-NetFirewallRule -DisplayName "ExampleVM inbound block" -Direction Inbound -Action Block -RemoteAddress 10.77.77.0/24 -Profile Any
   ```

   有効な受信ブロック規則が表示されます。VM 名とサブネットは、例と異なる場合は読み替えます。

実機確認では、この規則がないとゲストからホストのファイル共有用ポート 135、139、445 に接続できました。

### 仮想マシンを作る

1. **操作**の **新規**を選びます。
2. **仮想マシン**を選びます。

   **仮想マシンの新規作成ウィザード**の **開始する前に**が表示されます。

3. **次へ**を選びます。

   **名前と場所の指定**が表示されます。

4. **名前**に `ExampleVM` と入力します。
5. 保存先を選ぶ場合は **仮想マシンを別の場所に格納する**にチェックを入れます。
6. チェックを入れた場合は **参照**からフォルダを選びます。

   100 GB 以上空いているローカルドライブを使えます。フォルダは OneDrive の外に置きます。

7. **次へ**を選びます。

   **世代の指定**が表示されます。

8. **第 2 世代**を選びます。
9. **次へ**を選びます。

   **メモリの割り当て**が表示されます。

10. **起動メモリ**に `8192` MB と入力します。ホストの空きメモリが少なければ `4096` MB でも動きます。
11. **この仮想マシンに動的メモリを使用します**は表示された設定のままにします。
12. **次へ**を選びます。

    **ネットワークの構成**が表示されます。

13. **接続**で `ExampleVmSwitch` を選びます。
14. **次へ**を選びます。

    **仮想ハード ディスクの接続**が表示されます。

15. **仮想ハード ディスクを作成する**を選びます。
16. **サイズ**に `64` GB と入力します。
17. **次へ**を選びます。

    **インストール オプション**が表示されます。

18. **ブート可能なイメージ ファイルからオペレーティング システムをインストールする**を選びます。
19. **参照**から Windows の ISO を選びます。
20. **次へ**を選びます。

    **要約**が表示されます。

21. **完了**を選びます。

    一覧に `ExampleVM` が **オフ**で表示されます。

次の設定が終わるまで VM はオフのままにします。 [Hyper-V のウィザード](https://learn.microsoft.com/ja-jp/windows-server/virtualization/hyper-v/get-started/create-a-virtual-machine-in-hyper-v)

### 初回起動前にハードウェアとセキュリティを設定する

1. `ExampleVM` を選びます。
2. **操作**の **設定**を選びます。

   VM の設定項目が表示されます。

3. **セキュリティ**を選びます。

   **セキュア ブート**と**暗号化のサポート**が表示されます。

4. **セキュア ブートを有効にする**にチェックを入れます。
5. **テンプレート**で **Microsoft Windows** を選びます。
6. **トラステッド プラットフォーム モジュールを有効にする**にチェックを入れます。
7. **プロセッサ**を選びます。

   **仮想プロセッサの数**が表示されます。

8. **仮想プロセッサの数**を `2` 以上にします。
9. **統合サービス**を選びます。

   サービスの一覧が表示されます。

10. **ゲスト サービス**にチェックを入れます。
11. **ネットワーク アダプター**を選びます。

    **仮想スイッチ**に `ExampleVmSwitch` が表示されます。

12. **OK** を選びます。

    一覧に VM が **オフ**のまま表示されます。

注記。ホストから VM にファイルを手動でコピーするには、**ゲスト サービス**が必要です。

### Windows を導入してゲストのアカウントを作る

ゲスト用のコマンドは、タイトルに VM 名がある **仮想マシン接続**ウィンドウの中で実行します。プロンプトには通常、ゲストのローカルユーザーのフォルダが表示され、ゲストのネットワーク アダプターは 1 つです。

1. **操作**で `ExampleVM` の **接続**を選びます。

   **仮想マシン接続**が表示されます。

2. 画面の大きさを選ぶダイアログが出たら、右上の **×** で閉じます。

   基本セッションでは **表示**の **拡張セッション**にチェックが入りません。再接続時も **×** で閉じると `vmuser` がサインインでき、ホストのドライブやクリップボードを共有する拡張セッションを避けられます。

3. **仮想マシン接続**で **起動**を選びます。

   **Press any key to boot from CD or DVD** が表示されます。

4. VM のウィンドウ内でキーを押します。

   **Windows 11 セットアップ**が表示されます。

5. 言語を選びます。
6. **次へ**を選びます。

   現行のインストールメディアではキーボードの選択画面が表示されます。

7. キーボード レイアウトを選びます。
8. **次へ**を選びます。

   セットアップの選択肢が表示されます。

9. **Windows 11 のインストール**を選びます。
10. 新しい仮想ディスクのファイルを削除することを確認するチェック欄を選びます。
11. **次へ**を選びます。

    **プロダクト キー**が表示されます。

12. Windows のプロダクトキーを自分で入力します。
13. **次へ**を選びます。

    キーに対応するエディションのライセンス条項が表示されます。

    セットアップでキーが通っても、その場ではエディションが選ばれるだけです。ライセンス認証は別で、ネット接続か、利用できる場合は電話などでのオフライン認証が必要です。ゲストは隔離したままにします。 [Windows のライセンス認証](https://support.microsoft.com/ja-jp/windows/activation/activate-windows-online-or-offline-using-installation-and-confirmation-id)

14. **同意**を選びます。

    インストール先の選択画面が表示されます。

15. **ディスク 0 の割り当てられていない領域**を選びます。
16. **次へ**を選びます。

    **インストール準備完了**が表示されます。

17. **インストール**を選びます。

    進捗が表示され、再起動後に Windows の初期設定が始まります。

18. 国または地域を選びます。
19. **はい**を選びます。

    キーボード レイアウトの確認が表示されます。

20. キーボード レイアウトを選びます。
21. **はい**を選びます。

    キーボード レイアウトを追加する画面が表示されます。

22. レイアウトが 1 つでよければ **スキップ**を選びます。

    初期設定の次の画面が表示されます。**デバイスに名前を付けましょう**まで進みます。

23. **デバイスに名前を付けましょう**でデバイス名を入力します。

    英字、数字、ハイフンで 15 文字以内にし、個人情報を入れません。

24. **次へ**を選びます。

    再起動があれば、その後にセットアップ方法の選択肢が表示されます。

25. **職場または学校用に設定する**を選びます。
26. **次へ**を選びます。

    職場または学校のサインイン画面が表示されます。

27. **サインイン オプション**を選びます。

    **代わりにドメインに参加する**が表示されます。

28. **代わりにドメインに参加する**を選びます。

    ローカルアカウントの作成画面が表示されます。

29. **このデバイスを使うのはだれですか?** で専用のローカル管理者名を入力します。
30. **次へ**を選びます。

    パスワードの画面が表示されます。

    セキュリティの質問が表示されます。

    ローカル管理者の Windows デスクトップが表示されます。

38. `net user vmuser * /add` を実行します。

ISO によって画面名が異なります。ローカルアカウントで設定できるメディアを使います。

### ゲストのアダプターにアドレスを付ける

1. ゲストで **Windows PowerShell** を **管理者として実行**します。
2. ゲストで `Get-NetAdapter` を実行します。

   ゲスト側のアダプター名が表示されます。

3. ゲストで次のコマンドを実行します。必要なら `Ethernet` を実際のアダプター名に読み替えます。

   ```powershell
   New-NetIPAddress -InterfaceAlias 'Ethernet' -IPAddress '10.77.77.2' -PrefixLength 24
   ```

   ゲスト側のアダプターに新しいアドレスが表示されます。

4. ホストで `ipconfig /all` を実行します。
5. ゲストで `ipconfig /all` を実行します。

   両側の専用アダプターに例の固定アドレスが表示され、デフォルト ゲートウェイと DNS サーバーの表示は空です。

注記。両側の専用アダプターはデフォルト ゲートウェイを空にし、DNS は手入力せず自動取得のままにします。アドレスの設定で止まったら再実行する前に `ipconfig /all` で対象を確認します。

### ゲストに Python を導入する

1. ホストで、手順 2 の **Python の Windows 向け配布**から Python 3.13 のリリースページを開きます。
2. **Files** に **Windows installer (64-bit)** があるか確認します。

   ソースのアーカイブしかなければ、このインストーラーがある別の 3.13 のリリースを選びます。

3. Windows インストーラーをホストのダウンロード フォルダに `python313.exe` という名前で保存します。
4. VM の起動中に、ホストの管理者用 Windows PowerShell で次のコマンドを実行します。

   ```powershell
   Copy-VMFile -Name ExampleVM -SourcePath "$env:USERPROFILE\Downloads\python313.exe" -DestinationPath 'C:\SoraFromHost\python313.exe' -FileSource Host -CreateFullPath
   ```

   ゲスト側に `C:\SoraFromHost\python313.exe` が表示されます。

5. ゲストのローカル管理者として `C:\SoraFromHost\python313.exe` を開きます。
6. **Customize installation** を選びます。
   **Optional Features** の **py launcher** の横にある **for all users** は任意です。

7. **Next** を選びます。

   **Advanced Options** が表示されます。

8. **Advanced Options** で、Python 本体の **for all users** にチェックを入れます。
9. **Customize install location** に `C:\Program Files\Python313` を指定します。ドライブはゲストの Program Files の場所に合わせます。
10. **Install** を選びます。

   **Setup was successful** が表示されます。

11. **Close** を選びます。
12. ゲストの **エクスプローラー**で導入先のフォルダを開きます。通常は `C:\Program Files\Python313` です。

    フォルダに `python.exe` が表示されます。

13. ゲストの Windows PowerShell で次のコマンドを実行します。

    ```powershell
    & "$env:ProgramFiles\Python313\python.exe" -c "import ssl; print(ssl.HAS_PSK)"
    ```

    `True` が表示されます。

14. ゲストのローカル管理者からサインアウトします。
15. 画面の大きさを選ぶダイアログが出たら **×** で閉じます。
16. ゲストに `vmuser` としてサインインします。

    標準ユーザーのデスクトップが表示されます。

注記。コピーが止まったら VM の起動状態、**ゲスト サービス**、コピー先を確認してから再実行します。Python の導入が止まったらインストーラーを開き直し、**Repair** が表示されれば使い、TLS-PSK を確認します。 [Python インストーラーの設定](https://docs.python.org/3.13/using/windows.html)

## 4. ホストの設定を作る

1. ホストの Windows ユーザープロファイルの直下に自分専用の `VmControl` フォルダを作ります。
2. その中に空の `send` フォルダを作ります。
3. その中に別の空の `receive` フォルダを作ります。
4. 次の JSON の絶対パスを自分の環境に合わせて書き換え、`%USERPROFILE%\.config\sora-commander\vm-control.json` として UTF-8 で保存します。

```json
{
  "vm_name": "ExampleVM",
  "address": "10.77.77.2",
  "bind_local": "10.77.77.1",
  "port": 47700,
  "key_file": "C:\\Users\\YOUR_NAME\\VmControl\\vm-guest.key",
  "send_folder": "C:\\Users\\YOUR_NAME\\VmControl\\send",
  "receive_folder": "C:\\Users\\YOUR_NAME\\VmControl\\receive",
  "max_minutes": 30,
  "max_inputs": 200,
  "tools": ["screenshot", "wait", "elements", "click", "double_click", "move", "drag", "scroll", "type", "keypress", "file_put", "file_get"]
}
```

   末尾に `.txt` が付いていない `vm-control.json` が表示されます。

5. ChatGPT の通常のファイルツールから受信ファイルを読めるようにする場合、`read:C:\Users\YOUR_NAME\VmControl\receive` を実際のパスに読み替え、`%USERPROFILE%\.config\sora-commander\allowed-roots.txt` に追加します。

   次回起動後、ChatGPT の通常のファイルツールから受信フォルダ内のファイルを読めるようになります。

注記。JSON ではバックスラッシュを重ね、通常のローカルフォルダの絶対パスを直接書きます。上限は 4,096 バイトです。10 項目をそれぞれ 1 回書きます。ポートは 1024～65535、時間は 1～30 分、入力は 1～200 回です。`tools` に `screenshot` を残し、不要な権限は省きます。鍵と送信フォルダは許可ルートの外に置き、`read:` の親子にフルアクセスのルートを置かないでください。存在しない許可フォルダは作成してから再起動します。すべての行がスキップされると起動が止まる場合があります。 [許可フォルダと再起動](INSTALL.ja.md#自分のプロジェクトのフォルダを許可する)

## 5. ホストでゲスト用の束を作る

1. Sora Commander のフォルダで **コマンド プロンプト**を開きます。
2. 次のコマンドを実行します。

   ```bat
   tools\vm-setup.cmd make-guest --guest-user vmuser --out "%USERPROFILE%\VmControl\vm-guest"
   ```

   `Guest bundle:`、SHA-256 の一覧、`Guest key:`、`Host key:` が表示されます。

3. 後のメンテナンス用に `vm-guest.json` のコピーを別の非公開フォルダに保存します。

   `vm-guest.manifest.json` を含む `vm-guest` の束と、別のホスト用の鍵がそろいます。

出力先の親には Sora Commander の外にある既存のローカルフォルダを指定します。初回は出力先の `vm-guest` フォルダも、設定したホストの鍵も存在しない状態で実行します。ユーザー名はローカルの名前だけを 20 文字以内で指定します。管理者コマンドは手順 7 で受信フォルダから実行します。届いた束をマニフェストと自動で照合します。

### 初回の `install.cmd` より前に止まったとき

1. このゲストで `install.cmd` を一度も実行しておらず、ホスト鍵が中断した初回導入のものだと確認します。
2. ホストで作った `vm-guest` フォルダがあれば削除します。
3. 中断した初回導入用のホスト鍵があれば削除します。
4. 上の初回用 `make-guest` を `--replace-key` と `--update` を付けずに実行し直します。

ゲストでは新しく送り直した束を使います。導入済みのゲストは手順 10 に進みます。`--replace-key` は導入済みゲストの鍵交換用です。

## 6. ホストの送信ショートカットを導入して送る

### 別の VM 名で入れ直す前に

1. ホストで **Windows+R** を押して **ファイル名を指定して実行**を開きます。
2. `shell:sendto` を実行します。
3. 古い VM の **送る**ショートカットを削除します。
4. 古い VM のデスクトップ ショートカットがあれば削除します。

ショートカットは同じ送信スクリプトと設定を参照します。入れ直すと古いショートカットも新しい VM に送信します。

### 送信ショートカットを導入する

1. ホストの Sora Commander フォルダで **Windows PowerShell** を開きます。
2. `Get-ExecutionPolicy -List` を実行します。

   各スコープの実行ポリシーが表示されます。

3. `RemoteSigned` を指定した Windows PowerShell プロセスでインストーラーを実行します。

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\tools\vm_host\Install-SendToVm.ps1 -VmName ExampleVM
   ```

   Windows の管理者確認が表示されます。

4. Windows の管理者確認に自分で応答します。

   `作りました:` が 2 行と `SHA-256` が表示されます。`%ProgramFiles%\SoraVmTools` に `Send-ToVm.ps1` と `send-to-vm.json` が入り、デスクトップと **送る**にショートカットができます。

注記。中身を確認したローカル配布物を使います。Windows がダウンロードしたスクリプトにインターネット由来の印を付けた場合は、中身を確認したうえで **プロパティ**の **許可する**が表示され、使用が認められていれば選びます。強制されている実行ポリシーに従います。 [Windows PowerShell の実行ポリシー](https://learn.microsoft.com/ja-jp/powershell/module/microsoft.powershell.core/about/about_execution_policies?view=powershell-5.1)

昇格を取り消した場合や途中で止まった場合は、導入した 2 ファイルと 2 つのショートカットを確認し、原因を解消してから同じ VM 名でインストーラーを実行し直します。両方のショートカットの表示とダイジェストを確認してから送信します。

### 束を送る

1. VM の起動中に、`vm-guest` フォルダ 1 個を丸ごと **ExampleVM へ送る**に重ねます。

   ホストの管理者確認が表示されます。

2. ホストの管理者確認に自分で応答します。

   送信先の VM 名とファイルの一覧が表示されます。

3. 送信先の VM 名とファイルの一覧を確認します。
4. `y` を入力します。
5. **Enter** を押して送信します。

   `終わりました。VM の … にあります。` と表示されます。

6. ゲスト内で、表示されたフォルダを開きます。

   `C:\SoraFromHost\<yyyyMMdd-HHmmss>-<32-hex-suffix>\vm-guest` が表示されます。

注記。実行のたびに異なる接尾辞が付きます。コピーが止まったら表示された途中結果のフォルダを確認し、そのフォルダで導入を進めないでください。確認済みの束を丸ごと送り直し、新しい送信先を使います。VM の鍵を送れるのは、初回導入用または鍵交換用の完全な束 1 個に含まれる場合だけです。

## 7. ゲストエージェントを導入する

1. `vmuser` として受信した束の `check.cmd` を開きます。

   正しい VM 名、`OK: standard user`、Python 3.13、TLS-PSK `True` と設定したゲスト側の IPv4 アドレスが表示されます。

2. 受信した束の `firewall-admin.cmd` を右クリックします。
3. **管理者として実行**を選びます。
4. ゲストの管理者確認に自分で応答します。

   終了コード 0 と、生成された接尾辞を持つ受信規則 `SoraVmAgent` の検証結果が表示されます。

注記。規則はホストの内部スイッチ側アドレスから、設定したゲストアドレスとポートへの TCP だけを許可します。Windows ファイアウォールは有効のままにします。受信マニフェストは束がそろっているか、記載された各ファイルが一致するかを確認します。鍵は別に扱います。エージェントの起動前に届いたばかりの束を使います。

途中で止まったら、表示された規則名と対象範囲を確認してからファイアウォールの手順に戻ります。コマンドは追加後の確認に失敗すると元に戻そうとします。再実行前に規則が残っていないことを確認します。規則が残っている場合は、既存規則と検査結果を確認してから先に進みます。

5. `vmuser` として受信した束の `install.cmd` を開きます。

   `OK: copied to` と終了コード 0 が表示され、鍵の ACL にゲストユーザー、SYSTEM、Administrators だけが表示されます。

途中で止まって元に戻り、`%LOCALAPPDATA%\SoraVmAgent` が存在しなければ `install.cmd` から再開します。残っていたら先に `check.cmd` を実行し、フォルダと鍵の ACL を確認します。初回導入の途中結果なら必要な記録を残して不完全なフォルダを整理してから再実行します。以前の正常な導入がある場合は手順 10 に進みます。

6. `%LOCALAPPDATA%\SoraVmAgent` を開きます。
7. `netcheck.cmd` を開きます。

   ホスト向けの全ポートが `timed out`、外部向けの TCP 検査が `timed out` または `unreachable`、DNS の名前解決が失敗か時間切れなら合格です。

コマンドが正常終了しても表示を確認します。ホスト向けに `timed out` 以外、外部向けに `connected` や `connection refused`、または判定不能や DNS の解決成功が出たら、アダプター、経路、手順 3 のホストの遮断規則を確認してから再検査します。

ゲストの出力を共有するには、出力が見えている状態でホストから VM ウィンドウのスクリーンショットを撮ります。クリップボードの共有はオフのままにします。

8. 設定の `tools` に従う場合は `start-full.cmd`、撮影と待機だけなら `start-view.cmd` を開きます。

   エージェントのコンソールが表示されます。ファイル転送を有効にしたフルモードでは `%USERPROFILE%\SoraVmFiles\inbox` と `%USERPROFILE%\SoraVmFiles\outbox` ができます。

9. 導入とエージェントの起動が成功したら、ゲストの受信した `vm-guest` フォルダを削除します。
10. ホストで作った `vm-guest` フォルダを削除します。

   導入済みのゲスト鍵、ホスト鍵、メンテナンス用の `vm-guest.json` のコピーが残ります。

注記。エージェントのコンソールと標準ユーザーのデスクトップは開いたままにします。一時的な 2 つの導入用の束には鍵のコピーが入っています。

## 8. ホストを VM ツールつきで起動する

### Broker モード

1. 起動中のトンネルのウィンドウで **Ctrl+C** を押します。
2. DEV Owner Broker が停止中なら、ホストで `tools\start-broker.cmd` を実行します。

   Broker が起動したことを確認できます。

3. Sora Commander フォルダから `tools\start-vm-tunnel.cmd` を実行します。

   `tools\mcp-broker-client-vm.cmd` を使うトンネルが 1 つ動きます。

### 直接起動モード

1. 起動中のトンネルのウィンドウで **Ctrl+C** を押します。
2. Broker が作動中なら導入ガイドに従って停止します。
3. トンネルの YAML の `command` を次のように設定します。空白を含まない実際の Sora Commander の絶対パスに読み替えます。

   ```yaml
   command: "cmd.exe /d /c C:/SoraCommander/tools/mcp-direct-vm.cmd"
   ```

4. `tools\start-usual-mode.cmd` を実行します。

   直接起動用の VM ランチャーを使うトンネルが 1 つ動きます。

### ChatGPT コネクタ

1. ChatGPT で Sora Commander コネクタのツールを更新します。
2. 現在のチャットでツールが更新されなければ、新しいチャットを開きます。

   ホストが開発モードで、有効な `vm-control.json` がある場合は次のツールが表示されます。

| ツール | 用途 |
| --- | --- |
| `vm_session_start` | VM セッションの承認を求める。 |
| `vm_session_status` | セッション、上限、転送状況を表示する。 |
| `vm_look` | 撮影する。許可済みの場合は画面の UI 名も取得できる。 |
| `vm_act` | ゲストに入力を送るか待機する。 |
| `vm_file_list` | ホストの送信フォルダとゲストの inbox、outbox の名前とサイズを列挙する。 |
| `vm_file_put` | 指定したホストのファイルをゲストの inbox に送る。 |
| `vm_file_get` | 指定したゲストの outbox のファイルをホストの受信フォルダに取得する。 |
| `vm_file_status` | 転送 ID で進捗を確認する。 |
| `vm_file_cancel` | 転送 ID で中止を求める。 |

注記。起動方法は 1 つ選び、その方法で必要なウィンドウを開いたままにします。 [ホストの起動](INSTALL.ja.md#5-起動する)

## 9. 動作を確認する

1. ホストの送信フォルダに小さなテキストのサンプルを用意します。
2. ゲストのデスクトップで **メモ帳**を開きます。
3. セッションの開始前に ChatGPT にゲストの撮影を頼みます。

   `VM_SESSION_REQUIRED` が返ります。

4. ChatGPT に `vm_session_start` でセッションの開始を頼みます。
5. ホストの承認画面で VM 名、権限、上限を確認します。
6. 自分で承認します。

   残り時間と **停止**ボタンのある **VM リース**が表示されます。

7. ChatGPT に `vm_look` で 1 回撮影を頼みます。

   ゲストの **メモ帳**が表示されます。

8. ChatGPT に `vm_act` を 1 回使って編集欄をクリックし、サンプルの単語を 1 つ入力するよう頼みます。

   **メモ帳**にその単語が表示されます。

9. ChatGPT に `vm_file_put` でサンプルを送るよう頼みます。

   ゲストの `inbox` にファイルが届き、転送完了時に SHA-256 が表示されます。進捗は同じ `transfer_id` で `vm_file_status` を使って確認できます。

10. メモ帳で **ファイル**を選びます。
11. **名前を付けて保存**を選びます。

    保存先を選ぶ画面が表示されます。

12. ゲストの `outbox` を含むフルパスで新しいファイル名を入力します。
13. **保存**を選びます。

    `outbox` に新しいファイルが表示されます。

14. ChatGPT に `vm_file_get` でそのファイルを取り出すよう頼みます。

    ホストの受信フォルダに新しいファイルが届き、転送完了時に SHA-256 が表示されます。

15. `Get-FileHash` を使い、両端のサンプルの SHA-256 をそれぞれの転送結果と照合します。
16. ホストの **VM リース**で **停止**を選びます。

    リースのウィンドウが閉じます。

17. ChatGPT にもう一度撮影を頼みます。

    新しいセッションを承認するまで拒否されます。

注記。ホストはロックを解除したまま立ち会います。フルモードで `click`、`type`、`file_put`、`file_get` を有効にします。1 ファイルは 1 GiB、1 セッションの転送累計は 4 GiB までです。受信ボリュームにはファイルの大きさに加え 10 GiB の空きが必要です。ファイル名は Unicode NFC で 120 文字かつ UTF-16 の 120 コード単位以内にします。パスの区切り文字、Windows の予約名や予約文字、制御文字、先頭や末尾の空白とピリオドは避けます。指定した send、receive、inbox、outbox だけを使います。**停止**でホストのリースが終わります。ゲストのコンソールで **Ctrl+C** を押すとエージェントも停止します。

## 10. ゲストを更新、交換、削除する

### 設定を保ったままコードを更新する

1. **VM リース**で **停止**を選びます。
2. ゲストエージェントを **Ctrl+C** で停止します。
3. 手順 5 のコマンドに `--update` を付けて実行します。
4. 手順 6 で鍵を含まない完全な束を送ります。
5. `vmuser` として、届いた束の `update.cmd` を開きます。

   `OK: updated` とコピーしたファイルのハッシュが表示され、導入済みフォルダのコードが更新されます。

6. 導入済みのフォルダから `netcheck.cmd` を実行し、手順 7 の合格条件を確認します。
7. 合格したら導入済みのフォルダからエージェントを起動し直します。
8. 動作を確認した後、両側の更新用の束を削除します。

注記。途中で止まったら再起動や再実行の前に、両方のフォルダと表示された状態を確認します。更新には同じ設定が必要です。導入済みの設定と鍵はそのまま使います。

### 設定を保ったまま鍵を交換する

1. **VM リース**で **停止**を選びます。
2. ゲストエージェントを **Ctrl+C** で停止します。
3. 古いゲスト鍵を復旧用に安全に保管します。
4. ホストで `make-guest` に `--replace-key` を付け、`--previous-guest-config` に保存した旧 `vm-guest.json`、`--previous-host-key` に現在のホスト鍵を指定し、新しい鍵を準備します。

   `Prepared host key:` が表示されます。ホストは引き続き古い鍵を使います。

5. 手順 6 で新しい束を送ります。
6. `vmuser` として導入済みのフォルダか、古い設定と一致する受信束の `remove.cmd` を開きます。

   古い導入の削除結果が表示されます。

7. `vmuser` として新しく届いた束の `check.cmd` を開きます。
8. `vmuser` として同じ束の `install.cmd` を開きます。

   新しい導入先と鍵の ACL が表示されます。

9. ホストで `tools\vm-setup.cmd activate-key` を実行し、鍵の準備に使った `--guest-user`、`--previous-guest-config`、`--previous-host-key` を指定します。

   `Activated host key:` と退避した旧ホスト鍵の場所が表示されます。

10. 導入済みフォルダからゲストエージェントを起動します。
11. 新しい承認済みセッションで接続を確認します。
12. 確認後に古い鍵のコピー、交換の記録、一時的な束を削除します。

注記。設定が同じ間は既存のファイアウォール規則を再利用します。ゲストの導入が失敗したらホストの旧鍵を維持し、古い設定とゲスト鍵で復旧します。切り替えで止まったらエージェントを停止したまま、表示された現用、準備済み、退避の各鍵パスを確認してから再試行や復元を行います。

### 機能を削除するか設定を変える

1. **VM リース**で **停止**を選びます。
2. ゲストエージェントを **Ctrl+C** で停止します。
3. ホストのトンネルを **Ctrl+C** で停止します。
4. ホストの設定が古いままの状態で `--update` を使い、鍵なしの束を作ります。
5. 手順 6 で旧 VM にその束を送ります。
6. 新しく届いた、設定が一致する束の `firewall-remove-admin.cmd` を右クリックします。
7. **管理者として実行**を選びます。
8. ゲストの管理者確認に自分で応答します。

   終了コード 0 と、設定が一致する規則の削除結果が表示されます。

9. `vmuser` として、設定の一致する束か導入済みのフォルダの `remove.cmd` を開きます。

   ゲストエージェントの削除結果が表示されます。

10. 古い受信束を削除します。
11. 必要なゲストのサンプルファイルを保管します。
12. 完全に削除する場合はゲストのファイル用フォルダを削除します。
13. ホストの遮断規則を削除する場合は、先に旧 VM をシャットダウンします。
14. VM またはサブネットの利用を終える場合は、ホストで **Windows PowerShell** を **管理者として実行**します。
15. VM またはサブネットの利用を終える場合は、手順 3 で付けた固有の表示名を指定してホストの古い遮断規則を削除します。

   ```powershell
   Remove-NetFirewallRule -DisplayName "ExampleVM inbound block"
   ```

   同じサブネットで VM の保護が引き続き必要なら、規則を残します。別のサブネットに移す場合は、VM を再起動する前に手順 3 で新しいホストの遮断規則を設定します。

16. 復旧が不要になったらホストの古い鍵と一時的な束を削除します。
17. 受信フォルダの公開が不要なら、`allowed-roots.txt` の該当行を削除します。
18. 完全に削除する場合は `vm-control.json` を削除します。
19. 完全に削除する場合は `%ProgramFiles%\SoraVmTools` を削除します。
20. 完全に削除する場合は 2 つの送信ショートカットを削除します。
21. 直接起動モードで完全に削除する場合は、トンネルの YAML の `command` を元に戻します。
22. 完全に削除する場合は、通常のランチャーで Sora Commander を起動します。
23. 設定を変える場合は、新しい設定で手順 4 からやり直します。
24. ホストを起動したら ChatGPT コネクタのツールを更新します。

注記。片付けが済むまで古い設定を保管します。削除が途中で止まったら表示された規則、残ったファイル、古い設定を確認します。新しく届いた、設定の一致する束で部分削除を続けられます。VM 名を変更したら、手順 6 のインストーラーを新しい VM 名で実行します。

## 11. 困ったとき

| 表示や状態 | 再開前に確認すること |
| --- | --- |
| `[HOLD] Development virtual environment not found:` | `tools\setup.cmd` を実行し、`.venv\Scripts\python.exe` を確認します。 |
| `[HOLD] The folder path contains a space.` または必要なファイルの不足 | 導入ガイドで Sora Commander のパスと必要なファイルを確認します。 |
| トンネルが既に動いているか、ポートが使用中 | 先に動いていたトンネルを止めるかポートの競合を解決してから、手順 8 に戻ります。 |
| `vm-control.json` が見つからない、無効、DEV Host が必要 | 手順 4 の名前、エンコード、パス、10 項目と、手順 8 の起動方法を確認します。 |
| 束の出力先またはユーザー名の拒否 | Sora Commander の外にある新しいローカルの `vm-guest` とローカルユーザー名を使います。再実行前に出力先と既存鍵を確認します。 |
| ポリシーで送信スクリプトが止まる、または `send-to-vm.json` が無効 | ポリシーを確認し、手順 6 を対象 VM 名で実行し直します。 |
| 入れ直しでコピーできないと表示される | 現行の配布物か確認します。旧版では、既存ファイルの置き換えで止まることがありました。手順 6 の再導入前の確認に従います。 |
| 束のフォルダを重ねてもファイルを重ねるよう求められる | 完全な `vm-guest` フォルダを重ねたことを確認し、手順 6 で現行の配布物から入れ直します。旧版では、重ねたフォルダのパスを取り違えることがありました。 |
| VM が見つからない、停止中、または **ゲスト サービス**が無効 | VM 名、状態、統合サービスを確認します。途中結果は表示された `<yyyyMMdd-HHmmss>-<32-hex-suffix>` の送信先で確認してから送り直します。 |
| `check.cmd` の `NG: administrator` | 設定した標準ユーザーでサインインします。このチェックは状態を直接表示します。 |
| `NG: use "Run as administrator".` または導入先からの管理者操作の拒否 | 届いたばかりの完全な束の管理者用 CMD を使います。 |
| `NG: bundle hash mismatch:` または `NG: unexpected bundle file set.` | 新しい完全な束を作成し、送信します。 |
| 規則が既にある、Block 規則がある、または検査結果が不明 | **セキュリティが強化された Windows Defender ファイアウォール**で、対象の規則と適用範囲を確認してから変更します。 |
| `firewall-admin.cmd` が受信規則を読めない、見出しがない、または適用範囲を確認できないと表示する | ゲストのファイアウォールで、失敗後に規則が残っているかも含めて確認します。旧版の束では Windows のファイアウォール出力を読めない場合がありました。初回導入の途中なら手順 5 で現行の配布物から新しい束を作り、手順 7 で再開箇所を判断します。 |
| ホスト向けの全ポートが時間切れで DNS も失敗したのに `netcheck.cmd` が NG になる | 外部向けの TCP 結果も確認します。旧版では DNS の結果を誤判定する場合がありました。導入済みのゲストは手順 10 の `--update` と `update.cmd` で更新し、導入済みフォルダから再検査します。 |
| `Nothing was done.` または `Some changes may have been made. Run check.cmd and look at the folder before trying again.` | 例外時の診断です。表示されたフォルダやファイアウォール規則を確認してから再開します。 |
| `VM_SESSION_REQUIRED`、`VM_SESSION_ENDED`、`OWNER_SESSION_UNAVAILABLE` | `vm_session_status` とホストの画面を見ます。ホストのロックを解除し、新しいセッションでは Owner の新しい判断を得ます。 |
| `DENIED`、`TIMED_OUT`、`PENDING` | Owner の判断に従います。`EXPIRED` は時間内に応答がない状態、`CLOSED` は画面を閉じた状態です。`PENDING` は元の `pending_id` だけを照会します。 |
| `VM_UNREACHABLE` | 再試行前にゲストのコンソール、設定、アダプター、受信規則、両側の鍵の一致を確認します。 |
| `PAUSED`、`UNKNOWN`、`OUTCOME_UNKNOWN` | 次の操作前に元の結果を確認します。入力は `vm_look`、転送は同じ `transfer_id` で確認します。中断した転送を再開する前に Owner に聞きます。 |
